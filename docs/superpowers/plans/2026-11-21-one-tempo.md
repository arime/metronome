# One Tempo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A song has one tempo, one time signature and one set of accents, with a backing track or without and with the track played or not. The dial, − / +, Tap tempo, the tempo sheet and Sync mode's tempo controls all change that one tempo as an ordinary edit (badge, Save changes, Revert). Sync mode's offset, count-in and mix are ordinary edits too. The Backing tracks switch only says whether the track is played. Stored songs keep their format: the backing-track part repeats the song's tempo, and a part whose tempo differs from the tempo part gives the song its tempo.

**Architecture:** Mostly deletion. `MetronomeModel` loses the tempo in effect (`tempoInEffect`, `settingsInEffect`, `applyTempoInEffect`, `applyTrackTempo`, `nudgeTrackTempo`, `setTrackTempo`), the saved-at-once machinery of Sync mode (`saveLoadedTrack`, `meterChanged`, `persistSoon`, `pendingSave`, `syncSettingSaveDelay`, `savePendingChanges`) and the tempo swap of the switch. `BackingTrack` loses `bpm`; `SongRecord` writes the song's tempo into the track part and reads it back as the song's tempo, and loses `keepTrackTempo`. One thing is added: the metronome's working copy of the loaded track's offset, count-in and mix, `TrackSettings`, held by the model like `settings`, compared by `isEdited`, written by `saveChanges`, set back by `discardChanges` and kept between launches by `SettingsStore`.

**Tech Stack:** Swift, SwiftUI, Swift Testing. Build with `scripts/build.sh`, test with `scripts/test.sh` (extra arguments go to xcodebuild, e.g. `scripts/test.sh -only-testing:MetronomeTests/OneTempoModelTests`). New files need no project edit: the project uses file-system synchronised groups.

**Spec:** `docs/specification.md`: sections 1, 2, 4, 5 (the table, Edited), 5.1 (the song's parts, The tempo in two parts, Only a part that really changed, the example), 6 (intro), 6.1 (Badge), 6.2, 6.3, 6.11, 6.12, 6.13 (Tempo stepper), 7.1, 7.2, 7.6, 7.9, 7.10, 7.11, 7.12, 8.2, 9.4, 10, 10.2, 10.3, 13, 14, 15. Read them before each task; the rules and copy are binding. No UI copy changes.
